1 Introducción 
Los datos de localizaciones del tipo pr ovincia, municipio,  localidad, calle, portal…  son informaciones 
ampliamente incorporadas en multitud de aplicaciones, bases de datos, registros o formularios de todos los 
Departamentos, órganos y entidades del sector público de la Comunidad Autónoma del País Vasco.  
Desde el origen del proyecto NORA se busca la normalización y uso de una base de referencia para todos, así 
como facilitar la integración de dicha información en estas múltiples aplicaciones.    
Un ejemplo ilustrativo de este uso podrían ser los datos relativos a la sede social de una empresa que participa 
en la tramitación de un expediente para un departamento X.  Esto permitirá localizar sobre un mapa todas las 
empresas, así como agrupar datos por localidad o sección censal, o incluso explotar espacialmente la base de 
datos combinándola con datos de otra posible base de datos de población para calcular personas qu e viven a 
una determinada distancia de una supuesta serie de empresas potencialmente contaminantes. 
Eustat mantiene el conjunto de datos denominado  “Callejero de la Comunidad Autónoma del País Vasco ” que 
se compone de los Portales Oficiales del País Vasco más aquellos edificios que, si bien no tienen una dirección 
oficial, son de interés, almacenando el bloque, el número y el portal bis. Además, dispone de una capa de ejes 
de calles, la cual recoge un sistema reticular que se extiende por todos los viales de la Comunidad Autónoma 
Vasca comunicando todos los portales entre sí. El mantenimiento de este conjunto de datos requiere un esfuerzo 
y una constante coordinación con todos los ayuntamientos de la CAE, incluyendo la gestión de altas 
provisionales o incidencias provenientes de sus múltiples usos en organizaciones como Osakidetza o Industria. 
 
Los objetivos principales del proyecto han sido: 
- Establecer un marco de trabajo a nivel de datos con el Eustat con el fin de  garantizar que los datos 
disponibles en Eustat y los ofrecidos estén en concordancia. 
- Construir Servicios de valor añadido que puedan ser utilizados de forma horizontal. 
- Integrar dichos servicios en el geolocalizador de geoEuska di, así como con el API geoEuskadi para 
construir aplicaciones. 
 
Desde la puesta en marcha de la primera solución de acceso a datos de localización sobre el año 2008, se han 
ido actualizando diariamente los datos alfanuméricos, y trimestralmente los datos geográficos, así como 
evolucionando los componentes tecnológicos de los servicios NORA. 
Actualmente la amplia mayoría de aplicaciones en Gobierno Vasco emplean los servicios NORA para almacenar 
datos de lo calización y dicha capacidad permite la geolocalización directa en el territorio de estos datos de 
localizaciones. 
También el geolocalizador de geoEuskadi, así como los diferentes componentes, disponen de capacidades para 
consumir, consultar y ubicar en el mapa datos provenientes de los servicios NORA.

2 API REST 
Se ha definido un API que posibilita interrogar los datos de territorio disponibles. Las funciones y sus 
correspondientes parámetros son los mismos y lo único que cambia es la forma de invocarlas dependiendo de 
la tecnología utilizada. 
Para obtener más información sobre las entidades ver Anexo I. 
Posibilita obtener datos mediante peticiones Web Service de tipo REST. 
El API está pensado para obtener datos de localizaciones mediante peticiones estándar Web Services REST 
sin requerir ninguna librería específica. Las invocaciones son realizadas de forma síncrona.  
La información se puede obtener en formato JSON o en formato JSONP para evitar problemas de cross-domain.

 public String callRestService(String urlString) { 
  StringBuilder result = new StringBuilder(); 
  try { 
   URL url = new URL(urlString); 
   HttpURLConnection conn = (HttpURLConnection) url.openConnection(); 
   conn.setRequestMethod("GET"); 
   BufferedReader rd = new BufferedReader(new 
InputStreamReader(conn.getInputStream())); 
   String line; 
   while ((line = rd.readLine()) != null) { 
    result.append(line); 
   } 
   rd.close(); 
  } catch (IOException e) { 
   e.printStackTrace(); 
  } 
  return result.toString(); 
 } 
 
 public List<JsonObject> parseJsonResponse(String jsonResponse) {  
  List<JsonObject> dataObjects = new ArrayList<JsonObject>(); 
  JsonParser parser = new JsonParser(); 
  JsonElement element = parser.parse(jsonResponse); 
  if (element.isJsonArray()) { 
   JsonArray jsonArray = element.getAsJsonArray(); 
   for (JsonElement jsonElement : jsonArray) { 
    JsonObject jsonObject = jsonElement.getAsJsonObject(); 
    dataObjects.add(jsonObject); 
   } 
  } 
  return dataObjects; 
 } 
 
 public List<JsonObject> parseJsonpResponse(String jsonpResponse) {  
  String jsonResponse = jsonpResponse.substring(jsonpResponse.indexOf("(") + 1, 
jsonpResponse.lastIndexOf(")")); 
  return this.parseJsonResponse(jsonResponse); 
 } 
}

3.1 Entidades 
El proyecto maneja 14 entidades de datos de Territorio: país, autonomía, provincia, comarca, municipio, entidad, 
localidad, barrio, distrito, seccion, calle, portal, tipo de vía, edificio. 
Las Funciones disponibles sobre las entidades definidas posibilitan básicamente buscar en base a descripciones 
y claves. 
En todas las funciones existe la posibilidad de decidir la profundidad de los resultados mediante una propiedad: 
withParents. Por ejemplo, es posible realizar una búsqueda de municipios obteniendo únicamente los datos 
propios del municipio (id, idProvincia, descripcionOficial) para cada resultado. Pero también es posible realizar 
la misma búsqueda y obtener para cada uno de los  resultados información en profundidad (provincia, comarca 
y autonomía).
